# SparkyFitness 与 openGym 数据归属及同步规则

更新日期：2026-10-31（Asia/Shanghai）。

本文记录已确认的业务规则，不代表所有功能均已验收。修改数据维护方、同步方向或删除语义，必须重新获得用户确认，不能因为两端都有同名字段就自行增加双向同步。

## 一、总体职责

- **SparkyFitness 负责整体统筹**：身体健康数据汇总、每周训练部位和时段、main、休息安排、碳水循环和饮食计划。
- **openGym 负责具体训练**：在健身房决定动作、使用 AI 教练或模板、记录每次训练的动作、组数、次数和负荷。
- 两个项目独立运行、独立账号，不合并代码；通过明确配对的两个账户交换数据。
- 每类同步数据只有一个维护方，接收方保留只读副本。“集成有两个方向”不等于“同一种数据双向编辑”。

## 二、数据归属与方向

| 数据 | 维护方 | 当前同步方向／边界 |
| --- | --- | --- |
| 体重、体脂率、围度及受支持的自定义身体测量 | SparkyFitness | SF → openGym；18 项默认围度已对齐，既有字段名保留，以明确的字段及单位映射进入 openGym 原生项目 |
| 目标体重 | SparkyFitness | SF → openGym；属于目标，不是当天测量值 |
| 每周体重变化目标／目标区间 | 各自管理 | 不纳入同步 |
| 按日期的训练部位、时段、main 和休息安排 | SparkyFitness | SF → openGym，展示为每日训练提示 |
| 碳水循环、饮食计划、食物及营养数据 | SparkyFitness | 不向 openGym 同步 |
| openGym 记录的已完成训练，包括修改和删除 | openGym | openGym → SF |
| SF 自己创建的已完成训练 | SparkyFitness | **不向 openGym 同步** |
| 手表／Health Connect 导入 SF 的运动 | 原有健康数据入口 | **目前不向 openGym 同步**；未来完整运动统计另行设计 |
| openGym 来源动作信息 | openGym | 向 SF 提供来源身份、必要动作信息及训练快照；不反向修改 openGym 动作库 |
| 个人训练照片、动作检查视频 | openGym | openGym → SF，归档文件及元数据，按训练关联 |
| 身体进度照片 | openGym | openGym → SF，按日期私有归档，在 SF 网页和手机端的进度照片页面单独只读展示；不强行创建训练或指定正面／侧面等拍摄角度 |
| 官方动作动画及授权媒体 | openGym | 不复制到 SF，不引用原媒体 URL 绕过授权限制 |
| 用户自定义动作附带媒体 | openGym | 未单独确认复制范围，不能自动套用个人训练附件规则 |
| AI 教练问卷、对话、提案、复盘和撤销过程 | openGym | 不复制到 SF；确认并保存的实际训练按训练规则同步 |
| 器材配置、健身房资料、会员码及提醒 | openGym | 不同步；但训练重量口径等必要语义须随训练保留 |
| 密码、会话、AI 密钥、语言、主题等配置 | 各自管理 | 不同步；业务数据携带明确单位和日期语义 |

## 三、周安排与实际训练独立

1. 每周日先在 SF 安排下一周每天练什么部位、何时练、哪次是 main，以及休息日。
2. SF 据此制定高／中／低碳及饮食计划。
3. openGym 以备注式每日提示展示安排，无需先建动作模板，不改写私人备注，也不将提示作为豁免训练提醒的缺训备注。
4. 到健身房后再在 openGym 决定动作和负荷。同日允许多场独立训练，每次可以任选或重复使用模板。
5. 实际训练独立回传，不关联计划场次，不要求匹配早晚提示，不自动重排周安排或重算已保存的饮食。

每场实际训练的稳定 ID 用于去重、修改和删除，不是计划场次 ID。当天计划为休息，也不阻止临时记录训练。

## 四、修改与删除

### openGym 来源训练

- 在 openGym 创建、修改或删除，自动同步到 SF。
- 修改更新原来的来源记录，不应每改一次就新增一份训练。
- SF 中的导入训练只读：界面不提供编辑／删除，后端也执行来源保护。需要更改时回 openGym 操作。
- 来源删除移除对应训练及其动作／组，不得影响其他训练、身体测量、周安排或饮食。
- 删除训练会移除对应附件引用，不等于删除同日期的所有照片，也不等于物理清空全部归档文件。独立身体进度照片不随该训练删除。

### SF 本地训练

- 可按 SF 原有规则编辑、删除。
- 本来就没有发到 openGym，因此修改、删除也不向 openGym 发出对应操作。
- 不增加隐式反向同步，不仅凭日期或名称与 openGym 记录自动合并。

### 身体数据与连接

- 身体数据以 SF 为准，openGym 不反向覆盖受管副本。具体字段清空／删除按身体数据契约处理，不能套用训练删除逻辑。
- 暂停或解除连接不等于删除历史；清理来源数据须另行明确确认。

## 五、健康平台入口

- openGym 训练直接进入 SF，不再依赖 Hevy → Health Connect 的间接路径。
- 同一场 openGym 训练不应再经 Health Connect 重复导入；保留来源身份、去重及切换边界，不自动删除旧 Hevy 历史。
- 睡眠、步数、心率、智能秤和智能尺继续使用现有入口，不整体关闭 Health Connect。
- 手表记录的足球、跑步继续进入 SF。未来 E 类完整运动统计必须包含它们，但**当前并未因此实现 SF → openGym 的实际训练回传**。

## 六、同步机制与安全

- 保存成功后事件触发，不定时扫描业务数据发现变化。持久化队列的失败重试不等于业务轮询。
- 只在明确配对的账户间同步，不根据姓名、邮箱或日期猜测归属。
- 日常 API Key 不等同于集成配对凭据；服务器间事件使用配对后的签名认证，不交换用户密码或登录会话。
- 数据范围和方向固定，不通过勾选项任意改变。手动历史同步是独立操作，应幂等，不重复创建副本或覆盖更新版本。
- 来源 ID、修订版本、乱序保护、幂等和历史快照遵循完成契约；设计要求不等于已经全部完成实机验收。
- 个人媒体私有归档，经鉴权和归属检查后访问，不公开暴露 uploads 路径。

## 七、验收状态与待办

已获用户界面确认：体重、腰围、目标体重、单日及一周训练提示、跨日期训练回传、训练照片、修改训练后更新原记录、修改体重后更新原测量记录、周训练部位修改及 main 时段切换、改为休息日后清除旧训练提示并保留已完成训练。

清空单项围度：后台已验证当天腰围置空后，openGym 移除该项测量，保留当天体重和历史围度；用户已确认验收通过。该测试不等同于删除整个测量日或全部围度历史。

删除训练：后台验证通过，只移除指定训练及动作／组，训练照片解除关联；其他日期训练、独立进度照片及身体数据不受影响。用户在了解删除归属规则后接受继续验收。

同日多场训练：后台已验证两场独立保存和回传，不按日期覆盖；用户已确认界面显示正常并通过验收。

手动历史同步：用户通过界面分别触发两次，后台逐轮核对通过。第一次补齐两条已有历史体重；第二次没有新增副本，训练数量不变，已删除训练未恢复。当前身体数值、周提示、饮食和照片保留。本次证明对应测试数据下的补传及重复运行幂等，不代表所有故障恢复场景均已实机验收。

SF 侧暂停／恢复：用户手动暂停后，测试体重修改被持久化排队，openGym 保持旧值；用户恢复后，体重自动更新到同一条来源记录，队列清零，无重复，其他业务数据保留。

openGym 侧暂停／恢复：随后反方向独立实测通过。在 openGym 暂停后将早场测试卧推改为 42.5 kg × 8 次，SF 保持原来的 40 kg × 8 次，事件留在队列；用户恢复后自动更新到原 SF 训练／动作／组，pending 清零，无重复，其他数据保留。

应用容器重启恢复：随后独立实测通过。接收端停机时更新体重，确认入队；重启 SF 后原待发送任务 ID 和启用配对保留，再启动 openGym 后自动补齐到 83.7 kg，pending 清零，无重复，也无需重新配对或手动历史同步。数据库、上传挂载和原有业务记录保留。此项只覆盖本地两个应用容器的停止／启动及重启，不等同于已实测 Docker 守护进程、数据库重启、镜像升级／容器重建或暂停状态跨重启。

openGym 暂停状态跨重启：两阶段独立实测通过。暂停并修改早场测试卧推后重启 openGym API，暂停标记、配对和原待发送事件均保留；重启后继续观察十秒，SF 仍保持旧值，没有擅自恢复同步。用户手动恢复后，原事件送达，两边均为 45 kg × 8 次，原训练／动作／组 ID 保留，pending 清零且无重复，其他数据未变。此项不代表 SF 暂停状态跨重启或镜像重建也已验收。

本轮优化实现（2026-10-31）：

- **围度对齐**：SF 增加左／右前臂、手腕、脚踝内置字段，覆盖录入、显示设置、报告、健康数据接入和事件／历史快照。SF 左／右肱二头肌字段对应 openGym 左／右上臂；大腿、小腿及新增字段映射到原生项目，不落入 Other。不用自定义类别替代，不改已有字段名，不扩大体脂计算范围。
- **身体进度照片展示**：新增拥有者鉴权的照片元数据接口，读取已有归档，不要求重新上传。媒体仍走私有鉴权接口；来源删除后不再展示。网页和手机都接入现有事件通知刷新，手机另在页面进入／聚焦／手动刷新时读取，不增加轮询。
- **openGym 训练入口**：主页明确提供开始新训练及主动设置休息的入口；已完成训练不阻止新建另一场，已有进行中训练或历史编辑仍可继续。
- **休息与无安排的展示**：有覆盖当天的计划且当天无训练槽，表示明确休息；删除计划或无覆盖当天的计划，表示暂无训练安排。日期切换保留区别，不影响已完成训练，不生成私人休息备注或擅自豁免提醒。
- **连接成功后的配置展示**：SF 已连接／暂停时收起两个 URL 输入框，保留摘要及同步管理；显式编辑可取消，重新配对须确认，不静默改写签名绑定。更换 openGym 地址仍须明确断开旧连接后重新配对。openGym 收起主要导入邀请入口，保留重新配对入口；待配置／待批准等状态可恢复设置。

仍未纳入本轮：

- **E 类统计**：后续完善，并包含手表足球、跑步等运动。对应训练统计以 openGym 口径为准，不扩大到睡眠、营养等其他领域算法。
- 剩余媒体和故障恢复场景等未逐项验收的项目，不能认定已全部通过。

具体状态以[本日验收与待办](../plans/2026-10-31-sparkygym-test-and-followups.md)为准；测试日期和值不改变业务规则。
